# CitroenC4Monitor

Windows-приложение для пассивного мониторинга CAN автомобиля Citroën C4 II (B7).

## Статус

Это инструмент для пассивного захвата, маркировки и первичного статистического анализа классических SLCAN CAN-кадров. Программа показывает сырые кадры и статистику по CAN ID, но **не декодирует** параметры автомобиля и не отправляет CAN-команды.

## Установка

```powershell
py -m venv .venv
.\\.venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
py main.py
```

## Подключение

Укажите COM-порт адаптера WeAct (например COM3), скорость последовательного порта 115200 и скорость CAN, подтверждённую для выбранной шины. Начинайте только с пассивного прослушивания. Настройки контактов OBD и скорости CAN должны быть проверены по электросхеме именно вашего VIN/комплектации.

## Инструкция по проверке

Подробное пошаговое руководство на русском: [docs/TESTING_GUIDE_RU.md](docs/TESTING_GUIDE_RU.md). В нём описаны подготовка адаптера, безопасное подключение, первый захват, проверка кнопок руля и панели, сверка параметров с Diagbox и критерии достоверности.

## Безопасность и ограничения

- Не подключайте адаптер к неизвестным контактам и не замыкайте линии.
- Не отправляйте кадры, не кодируйте BSI/ABS и не меняйте конфигурацию блоков.
- Один адаптер обычно слушает только один CAN-канал одновременно.
- Этот прототип разбирает классические SLCAN CAN-кадры; CAN FD и диагностические протоколы PSA требуют отдельной реализации и проверки.
- Для полного доступа к ABS, BSI и другим ECU может потребоваться совместимый PSA диагностический интерфейс и Diagbox.

## Интерфейс и анализ CAN-трафика

Вкладка «CAN кадры» показывает поступающие кадры: время приёма, CAN ID, тип кадра, DLC, данные и исходную строку SLCAN.

Вкладка «Статистика CAN» обновляется по мере приёма кадров и показывает:

- общее число принятых кадров и число уникальных CAN ID;
- распределение кадров по типам;
- число кадров и долю каждого CAN ID в текущем захвате;
- число переходов между различными последовательными payload для каждого ID;
- номера байтов, которые менялись между последовательными кадрами этого ID (индексация с нуля);
- последний наблюдавшийся payload.

Статистика считается только в пределах текущего запуска захвата и сбрасывается при новом нажатии Start. Счётчик переходов — это число изменений payload между соседними принятыми кадрами одного ID, а не число нажатий кнопки или событий автомобиля. Список изменявшихся байтов также не является расшифровкой сигналов.

В модуле `citroen_monitor.analyzer` есть функция `compare_capture_rows(baseline, experiment)` для программного сравнения распределения payload по ID между двумя наборами строк CSV. Она возвращает число кадров, число вариантов payload, новые и отсутствующие варианты. В текущем графическом интерфейсе отдельной команды импорта/сравнения двух CSV пока нет.

Кнопка «Отметить событие» сохраняет пользовательскую метку и число уже принятых кадров на момент отметки. Это ориентир для анализа, не аппаратная временная синхронизация.

## Маркировка кнопок

Сначала запишите базовый трафик, затем нажимайте по одной кнопке с паузой и ставьте метку события в приложении. Повторите каждое нажатие несколько раз. Сигнал кнопки может идти по другой CAN-сети или LIN, поэтому отсутствие изменения в текущем захвате ничего не доказывает.

## Файлы

- `capture_*.csv` — принятые кадры (поля `timestamp`, `host_rx_monotonic_ns`, `can_id`, `frame_type`, `dlc`, `data`, `raw`)
- `events_*.csv` — метки действий пользователя (время компьютера, имя события и число принятых кадров на момент отметки)

Файлы создаются в текущем рабочем каталоге приложения. Сохраняйте отдельные захваты для базового состояния и каждого эксперимента.

## Исследование кнопок

На вкладке «Исследование кнопок» выполняется сравнение фонового трафика с несколькими отдельными попытками одного действия в рамках одного сеанса:

1. Начните пассивный захват и нажмите «Начать запись фона». Не нажимайте проверяемые кнопки.
2. Нажмите «Завершить этап».
3. Введите имя одного действия (например, `STEERING_VOLUME_PLUS`) и включите «Режим опытов».
4. Для каждой попытки нажмите «Начать попытку», выполните одно и то же действие и нажмите «Завершить попытку». Запишите не менее двух попыток; рекомендуется 5–10 с паузами и одинаковой техникой.
5. После последней попытки нажмите «Завершить этап», затем «Сравнить».
6. Сохраните отчёт `button_research_*.csv`.

Payload считается повторившимся, если он появился в нескольких отдельных попытках и отсутствовал в фоновой записи. Повторные кадры с тем же payload внутри одной попытки учитываются только один раз для оценки повторяемости. В таблице показывается число попыток, в которых встретилось значение, например `01 (3/5)`. По умолчанию кандидатами отмечаются значения, повторившиеся минимум в двух попытках.

Все этапы находятся в оперативной памяти приложения. Запуск нового сеанса захвата сбрасывает исследовательские данные. Не смешивайте разные кнопки в одном наборе попыток; для следующей кнопки начните новую фоновую запись.

**Важно:** повторяемость не доказывает, что payload относится к кнопке. Периодические счётчики, контрольные суммы и фоновые сообщения тоже могут повторяться. Сопоставляйте одинаковые условия автомобиля и длительность записей, проводите контрольные опыты без нажатий и сверяйте результат с реакцией штатной системы/Diagbox. Программа не декодирует бит/сигнал.


### Битовый анализ кандидатов

После сравнения попыток интерфейс дополнительно показывает биты, чьё преобладающее значение в отдельных попытках отличается от фонового преобладающего значения. Индекс бита считается как `byte_index * 8 + bit_in_byte`; бит 0 — младший бит первого байта. В CSV отчёте такие позиции перечисляются в поле `candidate_bits` в формате `индекс:фон>кандидат`.

Это статистический фильтр, а не декодер: счётчики, контрольные суммы и периодические поля могут создавать повторяемые битовые изменения. Текущие попытки не разделяют автоматически фазы «нажато» и «отпущено», поэтому для подтверждения состояния кнопки нужны отдельные контролируемые записи нажатия и отпускания с независимой проверкой.
 
### Размеченные окна состояний кнопки

Для более строгого поиска используйте три окна внутри каждой попытки: «Окно: отпущено до», «Окно: нажато» и «Окно: отпущено после». В каждом окне подождите, пока накопятся кадры; в среднем окне удерживайте кнопку. Повторите полный цикл не менее двух раз. Дополнительная таблица показывает биты, которые имеют одинаковое однозначное значение в обоих окнах отпускания и противоположное значение при нажатии. Такие позиции также экспортируются в CSV в поле press_release_bits. Это только статистические кандидаты: периодические счётчики и контрольные суммы всё ещё могут совпадать с таким шаблоном.

 
### Надёжность записи опытов и временная статистика

В версии 2.4 запись одной попытки контролируется последовательным автоматом состояний: «отпущено до» → «нажато» → «отпущено после». Каждое окно должно содержать минимум 3 принятых кадра. Перескочить через окно, поменять порядок или завершить неполную попытку нельзя; незавершённую попытку можно отменить. Это предотвращает сравнение неправильно размеченных окон.

В общей статистике для каждого CAN ID добавлены средний, минимальный и максимальный интервалы между приёмами кадров. Они вычисляются по монотонным меткам времени компьютера при получении строк от USB/Serial адаптера. Это НЕ аппаратные временные метки CAN-контроллера: USB-пакетирование, буферизация, ОС и задержки чтения влияют на результат. Используйте эти интервалы для ориентировочной периодичности, а не для точного анализа арбитража или микросекундной временной структуры. В CSV захвата сохраняется поле host_rx_monotonic_ns, пригодное для вычислений внутри одного сеанса; оно не является календарным временем и не сравнимо между запусками.

Парсер SLCAN теперь проверяет шестнадцатеричный формат ID/DLC/payload, пределы стандартного (11-битного) и расширенного (29-битного) ID, длину payload и классический предел DLC=8. CAN FD по-прежнему не поддерживается этим парсером.


**Важное замечание о режиме адаптера:** приложение отправляет последовательность команд, совместимую с классическим Lawicel SLCAN (C, Sx, L), но пока не анализирует ответ/подтверждение адаптера и не проверяет фактический режим контроллера. Надпись «запрос listen-only» означает только отправку команды. До подключения к автомобилю проверьте, что именно ваша прошивка WeAct поддерживает эти команды и что L действительно включает listen-only. Если это не подтверждено документацией/исходным кодом прошивки, не подключайте адаптер к автомобильной шине.
